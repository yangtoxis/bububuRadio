# Discord Radio Bot

Специализированный Discord-бот **только для интернет-радио**. Обычное
воспроизведение музыки (YouTube/Spotify/поиск/очередь треков) в этом
проекте отсутствует по дизайну.

## Возможности

- Заранее заданные радиостанции (`src/config/stations.yaml`) — пользователи
  не могут добавлять или изменять станции, только выбирать из списка.
- Выбор станции через Discord Select Menu (`/radio`).
- Управление: `/pause`, `/resume`, `/stop`, `/leave`, `/volume`.
- Одно обновляемое сообщение с кнопками (play/pause, stop, сменить станцию,
  громкость, выйти) — не спамит канал новыми сообщениями.
- Автоматическое переподключение при обрыве потока (реконнект на уровне
  ffmpeg + полный перезапуск процесса с backoff при жёстком падении).
- Полностью независимые аудиосессии между разными Discord-серверами:
  разные сервера могут одновременно слушать разные станции без пересечения
  состояния (громкость, пауза, текущая станция — всё изолировано).

## ⚠️ Ограничение платформы Discord

Один бот-токен может иметь только **одно** голосовое подключение на **один
сервер** одновременно — это ограничение самого Discord, а не этого кода.
Изоляция в этом проекте реализована между **разными серверами**
(`AudioManager` → `Map<guildId, AudioSession>`); две параллельные сессии
внутри одного сервера потребовали бы отдельных ботов (отдельных токенов).

## Если голос не подключается ("The operation was aborted")

Если после выбора станции бот заходит в канал, но воспроизведение не
начинается, а в логе примерно через 20 секунд появляется
`Failed to start radio stream ... "The operation was aborted"` —
голосовое соединение не смогло дойти до состояния `Ready` (это UDP-хендшейк
с серверами Discord, отдельный от обычного HTTPS/API). Причины по частоте:

1. **Битый/нерабочий IPv6 на хосте.** Многие VPS и Docker-сети объявляют
   IPv6, который реально никуда не маршрутизируется. Начиная с Node 18,
   `dns.lookup()` может выбрать IPv6-адрес первым, и если он не работает —
   вместо быстрого fallback на IPv4 просто виснет до таймаута. Это исправлено
   в коде (`dns.setDefaultResultOrder('ipv4first')` в `src/index.js`) — если
   вы обновляете проект руками, а не через новый архив, добавьте эти две
   строки в начало `index.js`.
2. **VPN/DPI режет UDP.** Если бот запущен там же, где активен VPN (особенно
   через Reality/VLESS или похожие TCP-камуфляжные протоколы), голосовой
   UDP-трафик может не проходить, даже если обычный HTTPS работает
   нормально. Решение — гонять бота на отдельном VPS без VPN, а не на своей
   машине.
3. **Провайдер VPS фильтрует/лимитирует UDP.** Встречается реже, но
   бывает у бюджетных хостеров как антиDDoS-мера.

Для диагностики поставьте `LOG_LEVEL=debug` в `.env` — в логе появятся
строки `Voice connection state change`, показывающие, на каком именно шаге
зависает соединение (`signalling` ↔ `connecting` без выхода в `ready`
обычно указывает на пункты 1–3 выше).

## Стек

- **discord.js v14** — Discord API
- **@discordjs/voice** — голосовые подключения и воспроизведение
- **ffmpeg** (`ffmpeg-static`) — декодирование HTTP/HTTPS радиопотоков с
  автопереподключением (`-reconnect` флаги)
- **better-sqlite3** — хранилище для durable-настроек (не для активного
  состояния воспроизведения — оно всегда только в памяти)
- **js-yaml** — загрузка списка станций из `stations.yaml`

## Быстрый старт (Docker)

```bash
cp .env.example .env
# заполните DISCORD_TOKEN и CLIENT_ID
docker compose up -d --build
docker compose exec radio-bot npm run deploy-commands
```

Данные SQLite сохраняются в `./data` на хосте (volume), поэтому переживают
пересоздание контейнера.

⚠️ `@discordjs/opus` — нативный C++-модуль. Готовые бинарники есть не для
всех сочетаний Node/glibc, поэтому Dockerfile ставит полный тулчейн сборки
(`python3`, `make`, `g++`, `pkg-config`, `libopus-dev`) — без них `npm install`
падает на этапе `node-gyp configure` с ошибкой "Could not find any Python
installation".

## Быстрый старт (локально, без Docker)

```bash
cp .env.example .env
npm install
npm run deploy-commands
npm start
```

## Радиостанции

Единственное место, где задаются станции: `src/config/stations.yaml`.
У пользователей нет команды на добавление/изменение станций — только выбор
из этого списка через `/radio`.

```yaml
stations:
  - id: lofi-girl
    name: "Lofi Girl"
    description: "Lofi beats to relax/study to"
    url: "https://..."
    icon: ""
```

⚠️ URL-адреса в поставленном файле — примеры для демонстрации формата.
Публичные радио-потоки периодически меняют адрес — перед продакшн-запуском
проверьте каждый URL вручную (например, `ffplay <url>` или `curl -I <url>`).

## Структура проекта

```
src/
├── index.js                   — точка входа, обработка interaction'ов
├── deploy-commands.js          — регистрация slash-команд
├── commandLoader.js
├── commands/
│   ├── radio.js                 — /radio: открывает Select Menu станций
│   ├── pause.js
│   ├── resume.js
│   ├── stop.js
│   ├── volume.js
│   └── leave.js
├── interactions/
│   ├── radioSelectHandler.js    — обработка выбора станции
│   └── buttonHandler.js         — обработка кнопок управления
├── audio/
│   ├── AudioManager.js          — реестр независимых сессий (per guild)
│   └── AudioSession.js          — одна голосовая сессия: connection, player, текущая станция, громкость, пауза, автопереподключение
├── sources/
│   └── RadioSource.js           — обёртка над ffmpeg для одного радиопотока
├── radio/
│   └── RadioStationManager.js   — загружает stations.yaml (владелец-only)
├── database/db.js               — SQLite, только durable-настройки
├── config/
│   ├── env.js
│   └── stations.yaml            — единственный источник списка станций
└── utils/                        — embeds, кнопки, логгер, guard-проверки
```

## Что удалено по сравнению с музыкальным ботом

- YouTube, Spotify, Яндекс Музыка и весь код резолвинга источников треков
- Очередь (`Queue`), `/play`, `/skip`, `/shuffle`, `/loop`, `/queue`,
  `/nowplaying`
- Абстракция `AudioSource` с несколькими типами источников — остался
  единственный, специализированный `RadioSource`
- Соответствующие зависимости (`yt-dlp-exec`, `spotify-web-api-node`)

`/pause` и `/resume` теперь применимы к радио напрямую (пауза буквально
приостанавливает вывод звука в канал; сам поток на сервере-источнике
продолжает идти, поэтому при возобновлении возможен небольшой сдвиг —
это стандартное поведение для интернет-радио, а не баг).
